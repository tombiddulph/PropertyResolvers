## Structural property access

This release implements the complete structural property-access roadmap:

- Correct property eligibility, inheritance ordering, keyword escaping, and compilation-wide duplicate detection.
- Configuration, no-match, unsupported-shape, incompatible-type, and ambiguity diagnostics; a PR001 duplicate-removal code fix.
- Opt-in typed resolvers and `TryGet`, preserving property types and distinguishing absent properties from null values.
- Stateless, per-assembly `PropertyResolverDispatch` suitable for trimming and Native AOT.
- Incremental syntax discovery, cached metadata/configuration models, and incremental tracking/performance tests.
- Attribute and MSBuild namespace/output defaults, custom resolver names, and case-sensitive matching.
- Property aliases and null-safe nested paths, including nullable struct intermediates and inherited/interface properties.
- Real package-consumer validation on .NET 8, .NET 10, and .NET Standard 2.0, plus Native AOT execution.

### Migration from 0.x/1.x

- String output remains the default and existing `Get<Property>(object?)` APIs remain available.
- **Automatic shared-registry registration is now opt-in.** Prefer the generated `PropertyResolverDispatch`. Legacy applications can set `RegisterRuntime = true` on an attribute or `PropertyResolversRegisterRuntime` in MSBuild.
- **Duplicate runtime registrations now throw** instead of silently overwriting another resolver.
- String formatting is null-safe and uses invariant culture for `IFormattable` values.
- No-match/unsupported-shape warnings can fail builds that treat warnings as errors; correct the configuration or intentionally configure diagnostic severity.
- Generated code requires C# 10+ and Roslyn 4.11+ (Visual Studio 2022 17.11+ or a .NET 8.0.4xx SDK+).
- The main package now depends on the matching `PropertyResolvers.Attributes` package rather than bundling a second copy of that assembly.

See [the README](https://github.com/tombiddulph/PropertyResolvers#readme) for examples, complete type rules, configuration, and diagnostics.
